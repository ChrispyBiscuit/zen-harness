---
name: multi-part-request
title: Long multi-part request
triggers: and also, then, first... second... third, several things, a list of tasks, do all of the following
examples:
  - "clean the data, make a chart, write a summary and email draft"
  - "set up the project, add tests, write the README and a changelog"
  - "research three topics and compile a report"
  - "clean up the data, then chart it, then write a summary and a draft email about it"
  - "first set up the folder, second convert the files, third write the index page"
  - "I need three things: a table of the numbers, a short memo, and a slide"
applies_when: the request contains several distinct deliverables
---
**Done looks like:** every part delivered (or explicitly deferred), listed in the final answer in the order asked.
**Approach:** split into milestones in the checklist, one per deliverable, in dependency order; finish and verify each before the next; keep intermediate results in files/artifacts; report progress at milestones.
**Tools:** update_tracker (milestones = parts); artifact_create for the growing deliverable.
**Pitfalls:** blending parts into one long step; losing a part; polishing part one while parts three and four are untouched; context filling with raw results (keep them in files).
**Verify:** the final answer maps each requested part to what was delivered.
**Stop / ask:** if the parts conflict or one is infeasible, say which and continue with the rest.
